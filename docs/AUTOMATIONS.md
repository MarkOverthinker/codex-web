# 自动任务

侧栏 **自动任务** 提供两个专用视图：**任务管理** 与 **运行记录**，桌面和移动网页版均可使用。

## 配置和查看

1. 点击 **新建自动任务**，填写名称、每天运行时间、明确的时区、模型、思考强度、权限模式与固定提示词。
2. host 模式下可填写运行目录绝对路径，或选择已有目录收藏；留空使用每次新建的独立会话工作区。其他部署不开放自定义宿主目录。
3. 保存后可编辑、暂停、启用、删除或立即运行。**立即运行** 在暂停时也可使用，不改变每日排期。
4. **运行记录** 每 15 秒刷新，按任务筛选、每页 50 条。每次保留配置和提示词快照，展示排队、运行、完成、失败、中断、取消或跳过状态。点击 **打开任务会话** 查看完整过程和交付文件。

提示词作为新会话的第一条用户消息持久化，不自动叠加用户默认预设 Prompt；系统提示、目录 AGENTS.md 和既有执行策略仍正常适用。自动会话使用“任务名称 · 日期”标题，保留配置的模型、思考强度及权限，不修改普通新会话的偏好。

## 调度规则

- 当前支持每日一次，精度为分钟；调度器每 15 秒检查。时间使用任务自己的时区，不依赖浏览器或服务器的默认时区。
- 浏览器无需在线，但服务与 Codex 配置必须可用。进程启动即检查到期任务；`QUEUE_AUTO_START=false` 同时关闭自动调度与自动消费队列。
- 服务停机错过多个日期时，恢复后只补跑一次，记录原计划时刻和实际创建时刻；不会逐日补发历史任务。
- 夏令时导致当地时刻不存在时跳过当天；同一天重复的当地时刻只触发一次。
- 同一自动任务上一次仍在排队或执行时，本次记录为“已跳过”，不叠加新会话。不同任务仍服从既有会话/工作目录排队规则。
- 暂停期间不补跑，重新启用后从下一个计划时刻开始。手动运行与定时运行都会检查重叠。
- 配置在每次触发时重新验证。模型、思考强度、目录或身份配置无效时记录失败，不创建残缺会话；下一天继续尝试。可修正后立即运行。
- 删除自动任务仅停止后续触发，保留运行记录和已有会话，不取消已排队或运行的任务。需要停止当前执行时，请到对应会话操作。
- 用户停用、服务关闭或 Codex 更新维护期间不创建自动会话；维护结束后按补跑规则处理。

## 实现与边界

`server/automations.ts` 在现有 SQLite 数据库中建立 `automations` 和 `automation_runs` 表。日触发去重键、下一次运行时间、配置快照、会话、第一条消息及排队 Job 在同一个事务中写入；创建失败使用保存点回滚会话及消息，并保留失败记录。作业执行复用既有队列、租户 worker 和 UID 隔离，不在 Web 进程中直接执行提示词。

定时器由 `server/index.ts` 启动，关闭入口停止定时器后再等待已有作业。重启不会重新执行已持久化的同一日触发；已经开始的 Codex 作业仍使用项目现有的中断恢复规则。这保证的是调度/入队去重，不是任意外部副作用的 exactly-once；提示词涉及外部写入时应自行设计幂等性。

API 均沿用会话认证、写操作 CSRF 校验与按用户隔离：

| 方法 | 路径（相对 `/api`） | 功能 |
| --- | --- | --- |
| GET / POST | `/automations` | 列表 / 创建 |
| PUT | `/automations/:id` | 完整更新配置 |
| PATCH | `/automations/:id` | `{ "enabled": true/false }` |
| DELETE | `/automations/:id` | 软删除，保留历史 |
| POST | `/automations/:id/run` | 立即触发，返回 `runId`；实际结果见运行记录 |
| GET | `/automation-runs?automationId=…&offset=0` | 可选任务过滤、50 条分页 |

当前不支持 cron、每周规则、附件模板、通知或原生 Android 管理界面。选择完全访问会增加无人值守执行的影响范围，界面会在保存时要求确认；部署未开放的权限模式不能通过 API 绕过。

## 验证

- `node --import tsx --test tests/automations.test.ts tests/automation-api.test.ts`：时区、夏令时、补跑、持久化、事务回滚、重叠、认证、CSRF、用户隔离和历史。
- `npx playwright test tests/browser/automations.spec.ts`：桌面/移动端创建、编辑、启停、手动触发、历史、会话跳转、删除和错误反馈。
- `npm test` 与 `npm run lint`：仓库回归与前端类型检查。
