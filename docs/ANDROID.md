# 独立 Android 客户端

## 定位

`android/` 从 0.2.0 开始是 **Kotlin + Jetpack Compose + Material 3 独立原生客户端**。登录、任务列表、聊天、输入区和所有工具页面直接访问现有 `/api` 接口，核心页面不加载网页、不使用 WebView、不执行网页 JavaScript。0.1.0 的 WebView Activity 已移除。

这不是离线 Codex，也不是 OpenAI 官方 App。Codex CLI、任务执行、权限隔离、消息、线程、队列和文件仍由原有服务器管理；本次没有改动后端执行逻辑、数据库结构或 Web UID / tenant worker UID 的隔离。

版本定位是可安装的**原生预览版**，不能将它等同于已经完成真机、真实账号和全部功能等价验收的商业成品。网页版继续保留，不依赖原生客户端才能使用。

## 安装与连接

1. 安装 `codex-native-android-0.3.0-preview.apk`，启动 **Codex Native**。已安装同签名 0.2.1 预览版时直接覆盖升级，不要卸载。
2. 输入现有服务的 HTTPS 地址，例如 `https://example.org/codex-web/`。仅输入主机会补上 `/codex-web/`；自定义反向代理路径应明确填写。
3. 使用现有账号密码登录。新版不读取旧 WebView 或浏览器的登录 Cookie，必须重新登录。
4. 设置页支持退出、更换服务器、外观和字号。退出前尝试保存草稿，服务器上的任务不会因为 App 退出而停止。

要求 Android 8.0 / API 26 或以上，以及受系统信任的 HTTPS 证书。无需安装 WebView 作为客户端运行依赖；不提供明文 HTTP、自签证书绕过或内嵌密码地址。需要 VPN 时先连接 VPN。

从 0.2.1 开始，用户安装包使用独立的 `app.codexweb.mobile.preview` application ID、非调试构建及持久保存的预览签名。开发构建继续使用 `app.codexweb.mobile.debug`，正式 ID 为 `app.codexweb.mobile`。新版可与 0.1/0.2 开发包共存，**无需先卸载旧包**；本机 Cookie、未同步草稿不跨包名迁移，请保留旧包直到确认重要内容已同步。服务器任务无需迁移。后续预览版必须沿用同一签名，不得每次构建生成新密钥。

旧 0.1 与 0.2 交付包的包名相同但签名不同，已在模拟器安装记录中确认 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。这是一项已证实的交付缺陷，但不能仅凭 Flyme 的“无效或不兼容”概括提示认定用户手机也是此原因。原 0.2 包已包含 ARM64，APK 签名、16KB ZIP 对齐与 ARM64 ELF 对齐检查通过；本次没有盲目降低 target SDK 或绕过系统安全校验。未在 MEIZU 21 / Flyme 真机上验收。

若仍提示无效：先确认下载的是完整 `.apk`（不是网页或零字节文件），在系统文件管理器中打开；记录文件大小、错误原文和是否安装过旧版。需要进一步定位时，可从自己的电脑运行 `adb install -r codex-native-android-0.3.0-preview.apk` 获取 `INSTALL_FAILED_*` 原因。不要使用 `-t`、降级参数或先卸载来掩盖安装问题，也无需发送账号密码或完整系统日志。

## 手机交互与功能矩阵

0.3.0 保留 Web 的靛蓝、琥珀配色与项目组织方式，以原生交互适配小屏：

- 默认进入上次对话（首次登录选择首条任务）；新对话先提供输入框，明确发送或准备附件等操作时才创建服务端任务。
- 从左向右滑出任务抽屉，也可点左上角菜单。默认按项目分组，沿用收藏目录名称、自定义分类、置顶、隐藏与任务顺序；每组先显示 4 条，支持展开、搜索与整列滚动。
- 抽屉可切换按状态查看，并选择项目范围。状态以运行、排队及最近作业结果区分；旧服务器缺少 `latest_job_status` 时显示“未运行 / 状态未知”，不把空闲误标为完成。
- 底部“对话 / 工作台 / 我的”分开承载聊天、工具与账户设置；切换保留当前草稿和聊天阅读位置。软键盘展开时隐藏底部导航，给输入留空间。
- 执行中或有排队消息时，在输入框上方显示小型队列提示；点击向上展开原生面板，保留编辑、排序、引导、删除、停止与直接执行入口，关闭仍回到当前对话。
- 语音转写、上传和发送各自在对应按钮内显示加载圆圈，不显示全局页顶请求进度条。语音转写期间可以继续键入，完成后追加到最新输入，不自动发送。

下表是实现范围与入口，并不代表所有条目都已用真实账户逐项验收。

| 能力 | 原生入口与行为 |
| --- | --- |
| 登录、退出、账户密码、切换主机 | 原生连接页与设置页；账号密码只用于请求，Cookie 独立于浏览器 |
| 会话、新建、搜索、分类、排序、重命名、归档、删除 | 右滑任务抽屉、项目/状态切换、管理分类与任务工具；破坏性操作先确认 |
| 主聊天、Markdown、代码、表格、数学 | Compose 懒加载列表 + 原生 TextView/Markwon；文本可选择、复制 |
| 历史分页、引用、编辑重发、Fork | 加载更早消息；消息菜单；选中文本后可引用或侧边提问；编辑时可保留、移除或新增附件；保留原服务端编辑/Fork 语义 |
| 草稿与附件 | 本机加密备份 + 延迟同步服务端；输入区加号打开系统文档选择器；最多 12 个附件 |
| 发送与任务恢复 | 先同步草稿再 multipart 发送；使用服务端草稿附件；SSE + 前台轮询恢复任务状态 |
| 队列、编辑、排序、引导、删除、停止、直接执行 | 输入框上方队列提示 → 向上展开面板；也可从工作台或任务工具打开；执行过程默认折叠；编辑中的队列项保持服务器暂停语义 |
| 模型、API 源分组、推理强度、权限、预设 | 输入区模型按钮 → 底部选项面板；提升到完全访问权限需再次确认 |
| 文件、图片/PDF/文本预览、代码定位、下载与分享 | 文件独立页面；图片和 PDF 原生预览；代码引用调用受权限约束的 snippet API；系统保存位置；分享前提示链接访问范围 |
| 服务器文件附件、工作目录、收藏、默认目录 | 文件页与工作目录页；使用服务器能力开关与路径验证，不扩大读取权限 |
| 侧边聊天、多线程历史、上下文引用、提升主任务 | 侧边线程独占聊天界面；返回可回到父任务；提升操作复用原接口 |
| Git Review | 独立工作区/暂存区/分支选择与文件差异页，长行横向阅读 |
| API 源与模型管理、预设管理 | 设置页原生表单；保留模型窗口、推理强度、协议和可见性等配置 |
| 计费统计与费率、远程价格同步、历史重算 | 设置/任务工具 → API 统计；重算历史费率需确认，不在打开页面时自动执行 |
| 历史导入、归档恢复 | 设置页；从服务器已有会话导入，不读取手机上的 Codex 数据 |
| 语音输入、转写模型 | 原生麦克风授权与录音；最多 5 分钟；调用原转写接口并回填，用户确认后再发送 |
| 外观、字体、键盘、返回 | 浅色/深色/跟随系统；12–24sp；键盘参与布局；Enter 换行，发送按钮提交；原生窗口处理系统返回 |

设计原则：聊天页以单顶栏、消息与输入区为主，队列按需展开，文件、Review 等进入独立页面；高级功能不是删除，而是按需显示。主操作保留至少 48dp 的触控区域。

## 本地缓存

- 近期任务列表、项目配置、模型选项与已打开的对话快照按服务器和账号隔离，使用现有 Keystore 加密私有存储；打开任务先显示缓存再请求更新，成功后以服务器结果为准。
- 每个账号最多 16 个快照条目（包含目录与配置），单条上限 512 KiB、合计 4 MiB，7 天过期。过大的结果不缓存；相同内容 5 分钟内不重复写入。不是全部历史或文件的离线副本。
- 离线快照可阅读和保存本机文字草稿；切换页面不会强制发起草稿同步。刷新校验成功前禁止直接发送，不自动重试写请求。服务器明确返回 401/403/404 时移除对应会话快照，不继续显示已撤权历史。
- “我的 → 本地浏览缓存”清理当前账号的缓存，不删除登录信息、本机未发送草稿或服务器数据。缓存读写失败不阻断正常网络业务。
- 冷启动仍先校验服务端登录会话；完全离线冷启动不是本版支持范围。缓存改善已有会话内的切换与弱网阅读，不绕过认证，也不在本机执行任务。

本版服务器会话查询增加可选的 `latest_job_status` 字段，不改变表结构或执行器。更新客户端可先连接旧服务器，但准确的“已完成”分组需要同步更新并重新加载服务器。

## 状态一致性与安全

- 网络层只访问配置的 HTTPS origin 下的 API；拒绝跨来源请求和 API 路径逃逸。不跳过 TLS 校验，不自动跟随重定向，不自动重试写操作。
- Cookie 按服务来源限制发送。服务端 Cookie 和未同步文字草稿保存在 Android Keystore AES-GCM 保护的应用私有存储中；草稿按服务、用户名、会话分隔。禁用备份和设备迁移。
- 密码/API Key 不保存在客户端。输入密码字段在 Activity 重建后清空。源配置中的 API Key 仅提交到用户指定服务器。
- 本机草稿写入按顺序排队；同步结果只有与当前编辑版本一致时才清除脏标记，避免旧响应覆盖新输入。离线返回列表时保留本机副本。
- 发送请求若出现结果不确定的网络错误，保留本机文本并暂停重发/自动同步，要求用户核对服务器消息与队列。不能把网络错误当成“服务器一定没有执行”。
- SSE 按序号去重，合并迟到的快照；更换任务、退到后台或退出会取消旧连接。前台恢复后重新读取服务器。后台任务执行仍发生在服务器，不依赖 Android 进程存活。
- 文件上传走系统选择器，不申请全盘存储权限。下载在用户选择的系统位置写入，失败可能留下不完整目标文件，界面会明确提示。
- 原生预览限制读取 24 MiB；PDF/图片限制渲染尺寸；大文本最多预览 150000 字符，完整文件可下载。HTML/SVG 按文本或外部文件处理，不在 App 内执行网页。
- Markdown 外部链接先确认，再交给系统应用。图片不会因为一条 Markdown 外链自动向第三方主机发请求。
- 录音在 App 离开前台时停止并尝试转写，不自动发送；如果会话或账号已变化，不把旧录音上传到新任务。

## 当前差异与未完成验收

- 编辑表单尚未提交的文本和新选文件仅保留在当前编辑界面；系统销毁该界面后需重新填写/选择。服务器中的原消息、原附件及暂停编辑队列仍会保留；主聊天输入框使用独立的加密草稿恢复机制。
- 网页中的任意 HTML/Office 等交互式预览不复制到原生；可以下载到系统应用打开。Markdown 远程图片不自动加载，文件附件可手动打开。代码有等宽显示，但没有复制网页全部高亮/富内容渲染效果。
- 没有离线任务执行、完整离线消息库、推送通知、后台下载服务、实时语音通话、后台录音、相机直拍或系统分享接收。语音转写失败会报错，不承诺录音离线重试。
- 表单有原生入口和后端契约对接，但复杂源配置、真实计费、真实录音、PDF/图片、真实文件授权与全部侧线程操作仍需测试账号逐项验收。
- 无真机性能数字，不宣称已经达到 ChatGPT 商业 App 的流畅度。特别需要测试长 Markdown/代码/公式消息、低内存机型、系统字体放大与中文输入法。

## 工程结构

- `MainActivity.kt`：系统文件选择/保存、录音、外部链接、生命周期。
- `NativeApp.kt`：聊天、输入区、队列/选项面板、主题。
- `MobileShell.kt` / `TaskGroups.kt`：对话首页、项目/状态任务抽屉、底部导航与工作台。
- `SnapshotCache.kt`：账号隔离、有限大小、限时的加密浏览快照。
- `ToolsScreen.kt` / `NativeForms.kt` / `NativePreview.kt`：原生工具页、表单与文件预览。
- `ClientModel.kt`：会话状态、草稿顺序、发送保护、SSE/轮询恢复、导航。
- `NativeApi.kt` / `SessionVault.kt` / `Json.kt` / `ServerPolicy.java`：HTTPS、Cookie/CSRF、加密存储、数据转换与来源边界。

没有第二套任务执行器或数据库。API 字段继续以 `src/api.ts` 与服务器路由为准；修改后端协议时需同步测试两个客户端。

## 构建与验证

每次版本发布还必须同步固定下载页、APK、校验文件和更新说明，见 [标准发布流程](ANDROID_RELEASES.md)。仅在对话中提供附件不算完成发布。

依赖：JDK 17、Android SDK platform 36、Build Tools、Gradle Wrapper 下载网络。首次 Compose 构建会下载 Maven 依赖。可在未提交的 `android/local.properties` 配置 `sdk.dir`。

```sh
cd android
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
./gradlew :app:connectedDebugAndroidTest
```

第二条命令需要已启动的设备/模拟器。开发 APK 位于 `android/app/build/outputs/apk/debug/app-debug.apk`，仅用于开发测试，不作为稳定升级渠道。

用户预览构建需先准备持久保存并安全备份的签名密钥，在被 Git 忽略的 `android/preview-signing.properties` 设置以下四个属性（Java Properties 格式，不要提交真实值）：

```properties
storeFile=.signing/preview.jks
storePassword=REPLACE_WITH_PRIVATE_STORE_PASSWORD
keyAlias=preview
keyPassword=REPLACE_WITH_PRIVATE_KEY_PASSWORD
```

`storeFile` 相对 `android/` 解析。可用 `CODEX_ANDROID_SIGNING_PROPERTIES` 指定其他私有配置文件。未配置签名时预览构建必须失败，不回退到临时 debug 签名。此密钥与配置不随源码归档交付；丢失密钥会失去对既有安装的覆盖升级能力。正式发布仍需独立的签名与发行管理。

```sh
./android/gradlew -p android :app:testDebugUnitTest :app:lintPreview :app:assemblePreview
bash scripts/verify-android-preview.sh android/app/build/outputs/apk/preview/app-preview.apk "$EXPECTED_SIGNER_SHA256"
```

校验脚本需要 JDK、`ANDROID_HOME`、Build Tools 35.0.0（可用 `ANDROID_BUILD_TOOLS_VERSION` 修改）以及 unzip；证书 SHA-256 必须来自事先保存的可信签名证书记录，而不是从待验证 APK 临时取值。检查包名、固定签名、SDK、ARM64、非调试/非测试/非拆分标记及 ZIP 完整性和 16KB 对齐。用户预览与旧版共存、同签名覆盖安装应使用不带 `-t` 的 `adb install` 验证；模拟器通过不等于 Flyme 真机通过。

CI 的 Android development checks 工作流默认执行开发构建、单元测试和 lint，并保存报告；手动触发时勾选 `emulator_tests` 可额外运行 API 36 原生界面测试。CI 的临时 debug 签名产物明确标记为 development，不得作为可覆盖升级的用户预览包发放。

```sh
npm run lint
npm test
node --import tsx --test tests/android-api.test.ts
```

测试层次：

1. Android JVM：HTTPS 请求、Cookie/CSRF、路径与来源、重定向拒绝、SSE cursor、multipart、JSON 表单、草稿竞态、发送失败与恢复、快照隔离/过期/限额/撤权、项目分组与真实完成状态。
2. Compose instrumentation：**模拟 API** 的登录/聊天/工具/发送失败保护、右滑项目抽屉与展开、状态切换、底部导航保留草稿与阅读位置、队列面板、语音按钮局部加载和回填；另有真实 `MainActivity` 重建时连接字段保留与密码清空测试。
3. `tests/android-api.test.ts`：**真实 Express + SQLite、临时数据、关闭执行器自动启动**的原生协议流程，验证草稿/上传/发送/队列编辑/文件/侧线程/退出，不调用真实模型。

测试截图显示模拟内容，不代表已经连上用户生产服务。最新一次测试结果、环境与遗留失败记录在交付说明中。

## 发布前验收（需要时阅读）

- 至少两台真实安卓设备，含 API 26 与较新系统；中文软键盘、手势返回、旋转、字体放大、低内存恢复。
- 测试账号跑通登录/过期/换主机、真实任务、队列引导/停止、后台恢复、编辑/Fork/引用。
- 图片/PDF/多文件上传、服务器文件、权限拒绝、下载取消/中文文件名/大文件/断网、API 源与账单操作。
- 实际麦克风、转写模型、后台切换、拒绝与重新授权；确认没有未经用户确认自动发送。
- 对照功能矩阵检查业务结果，而不只是入口存在。继续保持网页版可用，未验收功能不得宣称完全等价。
