# 0.5.1：一级页面横向滑动切换

日期：2026-09-13。基线：已发布的 `0.5.0-preview` / versionCode 12。状态：实施前规划；本轮是源码内部里程碑，不是签名候选或公开发布。

## 更新计划

1. 协调 agent 固定手势范围、切换顺序、冲突边界与验收标准。
2. 实施 subagent 只修改一级页面容器及对应确定性测试，实现「对话 ↔ 工作台 ↔ 我的」横向分页和底栏联动。
3. 独立 QA subagent 不改生产代码，运行单元、构建和原生 UI 手势回归并记录证据；失败项退回实施方。
4. 协调 agent 审查差异、实际测试和文档同步；不自动提升版本号、构建签名候选或公开发布。

## PRD

### 用户故事

作为 App 用户，我希望在三个一级页面中直接左右滑动切换，并看到连续、跟手的页面过渡，同时仍可使用底部导航按钮。

### 功能要求

- FR-511：一级页面顺序固定为「对话、工作台、我的」；左滑进入右侧相邻页，右滑进入左侧相邻页，到达两端后不循环。
- FR-512：拖动过程呈现连续的横向位移，松手后平滑归位或落到目标页；底栏点击也使用同一分页状态和动画。
- FR-513：分页落定后 `HomeTab` 与底栏选中状态一致；切换期间不得发送消息、清空草稿、重置对话阅读位置或额外请求业务接口。
- FR-514：手势只在一级页面生效。工具详情页、模态弹窗、任务抽屉和键盘输入场景维持现有交互；系统返回逻辑与底栏的可访问标签继续有效。
- FR-515：在对话、工作台和我的三个页面验证双向相邻切换、端点不越界、快速滑动和短距离拖动回弹。

### 非目标与限制

- 不新增页面、不改变服务端协议、持久化、租户 UID 或发布配置。
- 不将本轮源码改动称为 0.5.1 已发布版本；真机厂商手势导航兼容性需要后续真实设备复核。
- 页面内部可横向滚动的内容应优先保留自身手势；本轮验收至少覆盖主内容空白区域的分页滑动。
