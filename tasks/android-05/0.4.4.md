# 0.4.4：对话效率与状态反馈

状态：内部开发里程碑已实现并通过主 agent 候选门禁，合入 0.5.0-preview；未独立发布。依赖：0.4.3；属于 [0.5 路线](../prd-android-05.md)。

## 更新计划

1. 给输入框提供清楚的发送、排队、录音和缓存只读语义；不改变服务器提交协议。
2. 优化消息阅读和辅助操作的视觉层级，使用上一版本主题；保留原生选择、引用、复制与侧线程入口。
3. 给“回到最新”明确文字或无障碍语义；在用户读历史时不强制拉到底部。
4. subagent 补充状态逻辑与界面测试；主 agent 验收异常发送及草稿安全后推进。

## PRD

### US-441：发送前理解将发生什么

作为用户，我需要知道输入将立即提交还是进入运行任务的队列，以及按钮不能用的原因。

- FR-441：空闲且可发送时标注发送；存在 activeJob 时提供加入队列语义；语音转写、发送中、缓存只读、结果不确定各自准确说明，不误用一个“加载中”。
- FR-442：错误/不确定状态的既有安全禁用继续生效；任何文案不得承诺自动重发或断网执行。
- FR-443：发送快照、草稿同步与附件事务不变；本轮不擅自开放 busy/sendUncertain 时编辑，不把模型保护误当作已有可编辑 UI。
- FR-444：输入反馈不重复占用多行常驻大卡片；按钮仍保留最小触控区域，长模型名省略，正文不被状态条盖住。

### US-442：更轻的连续阅读

作为用户，我需要快速找到作者和操作，同时滚动历史不被新消息强行中断。

- FR-445：消息作者、引用和操作使用统一主题层级；主要回答以阅读面为主，不新增头像装饰或每条大卡片。
- FR-446：用户不在底部时显示可达的“回到最新”入口；点击才滚到末尾；切换工作台回来保留位置。
- FR-447：复制、引用、编辑重发、附件、代码/数学渲染及远程图片安全策略不回退。

## 实施边界

允许：`NativeApp.kt`、独立 composer 状态纯函数文件和独立测试。尽量不改 ClientModel；如确有模型变更需求先向主 agent报告。不得修改底栏、工作台路由、后端或发布版本。
